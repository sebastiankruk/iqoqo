## 1. Docker Build Optimization (<500MB)

- [x] 1.1 Refactor `deploy/Dockerfile` multi-stage build: compile python wheels in `builder` stage, install pre-compiled wheels in `runtime` stage without compilers, and verify with `docker build` dry run. Rebuilt and measured against the published image. **1019.2 MB → 826.7 MB (-19%)**, verified by `docker image inspect` and a smoke test importing the app, `S3Service`, numpy/scipy/imagehash and tesseract inside the built image. Three substantive changes: (1) the builder now runs `pip wheel` into `/wheels` and installs nothing, replacing `pip install --user` whose leftover state was copied wholesale into the runtime; (2) the runtime installs with `--no-index --find-links`, so it can neither download nor silently compile a source distribution in a stage that has no compiler; (3) the wheels arrive via a BuildKit bind mount rather than `COPY --from`. That last one is worth 125 MB on its own and cost a rebuild to find: `COPY --from=builder /wheels` creates a real layer, and the `rm -rf /wheels` in the next step only writes a deletion *on top of* it, so the wheels shipped in the image forever. The first rewrite measured 1062.6 MB — worse than the original. **The <500 MB target is not reachable; deferred, not waived.** Measured floor: `site-packages` 421 MB, `/usr/lib/x86_64-linux-gnu` 117 MB, tesseract 15 MB, app 6 MB. Of the 421 MB, `scipy` + `numpy` + their bundled `.libs` are **167 MB** — 20% of the whole image — pulled in solely by `ImageHash==4.3.2`, which is used at `app/utils/images.py:91` for `phash` perceptual cover deduplication. Neither is imported anywhere else in `app/` or `scripts/`, and both are commented out of `requirements.txt`. Removing them still lands at ~660 MB. Reaching 500 MB would additionally require dropping tesseract OCR or a large part of botocore/grpc, i.e. removing features, not optimising the build. See §7.3
- [x] 1.2 Remove `rclone` system package and `/home/appuser/.config/rclone` setup from `deploy/Dockerfile` and `deploy/docker-entrypoint.sh`, verifying entrypoint permissions and startup logic. Done as part of §3, since removing the image's only caller of the CLI is what makes the package safe to drop. The entrypoint's read-only-HOME regression test is retained and extended to cover the new S3 half-configuration warnings
- [x] 1.3 Audit and prune `.dockerignore` to exclude development caches, test directories, local artifacts, and docs, and verify final image size meets `<500MB` target. Rewritten with the two distinct jobs separated in the comments, because they had been conflated: image size (anything the Dockerfile `COPY`s breaks the layer cache) versus build-context size (Docker ships everything unignored on every build). The largest omission was `graphify-out/` at 383 MB — never `COPY`ed, so invisible in the image, but sent to the daemon on every single build. Also added `codegraph-out/`, `.codegraph`, `.iqoqo-mykg`, `.iqoqo-mempalace`, `.tmp`, `logs`, `*.log`, `*.dump`, and generic Python packaging noise. The existing secret-critical rules were preserved and `!.env.test` re-admitted explicitly, because `.env.test` is tracked and a bare `.env.*` would have silently dropped it from the context. Size target: see §1.1 and §7.3 — not met, and not achievable without removing a feature

## 2. Production Nginx Configuration

- [x] 2.1 Create `deploy/nginx.conf.example` reference configuration with TLS termination, port 80 to 443 redirection, and modern SSL ciphers, verifying syntax with `nginx -t` validation script. Two separate server blocks: port 80 serves only the ACME challenge and redirects everything else to 443 (including requests that already claim HTTPS, so an unauthenticated caller cannot keep talking plaintext by sending the header), port 443 terminates TLS with a forward-secret suite list. TLS 1.0/1.1 and every CBC and 3DES suite from nginx's default are removed; `ssl_conf_command Ciphersuites` governs TLS 1.3, which nginx otherwise ignores `ssl_ciphers` for. Validated by `scripts/validate_nginx_example.py` (new), which renders the placeholders, wraps the file in the `http {}` context it is designed for, generates a throwaway self-signed pair so the TLS directives are actually read, and runs `nginx -t` — locally if installed, otherwise in a pinned `nginx:1.29-alpine` container. Wired in as `make validate-nginx`
- [x] 2.2 Add enterprise security headers (`server_tokens off;`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Content-Security-Policy`, and HSTS) to `deploy/nginx.conf.example` and verify headers via mock response test. All seven present, with `server_tokens off` and `X-Forwarded-Proto https` set at the edge rather than trusting the client's `X-Forwarded-Proto` (that would let a caller forge an `http://` origin for generated links). The CSP is documented as deliberately loose: `'unsafe-inline'` and `'unsafe-eval'` are required by Next.js, and the file says so and tells the operator to re-check before tightening, rather than shipping a CSP that breaks the login page. HSTS is set but **preload is not**, and the reason is written down: preloading is irreversible for a year and applies to all subdomains. Verified by `tests/bash/validate_nginx_example.bats`, which removes or comments out each header in turn and asserts the validator fails — a validator that passes everything would launder an unvalidated config as a validated one
- [x] 2.3 Configure rate limiting zones (`api_general` 20r/s, `api_scanner` 5r/s) and static asset caching directives (`/_next/static/` immutable, `/static/covers/` and `/static/gallery/` 30d) in `deploy/nginx.conf.example`. Zones are declared with their memory cost stated (10m ≈ 160k tracked addresses, ~10 MB each), and `limit_req_status 429` is set so a throttled caller gets a 429 rather than nginx's default 503. `/api/scan` additionally caps the body at 25m against the global 60m: it is the most expensive endpoint in the app and the one most likely to be abused for upload DoS. Caching is split deliberately: `/_next/static/` is content-hashed so it gets `immutable` for a year, while covers and gallery get 30d **without** `immutable`, because those filenames are not content-addressed and a redeploy must not be able to strand them in a browser cache

## 3. Native S3 Storage Service Migration

- [x] 3.4 Migrate cover caching in `app/utils/images.py` and `app/utils/llm_covers.py` from rclone to `S3Service`, verifying cover upload behavior. ## 8. Spec reconciliation (pre-archive)

Not part of the original scope. Added because archiving publishes this change's
delta into the main specs, and five existing specs had been left asserting
things this change made untrue. Archiving without reconciling them would have
produced a self-contradictory spec set — exactly the drift this change set out
to fix.

- [x] 8.1 `automated-backup-retention` — REMOVED. It described `BackupManager` and `rotate_and_archive_backups`, which were already unreachable before this change (no beat entry, unmounted `/data/backups`, empty listing on a missing directory). The spec had been asserting a retention policy no deployment enforced.

- [x] 8.3 `rclone-preflight-check` — REMOVED, plus an ADDED requirement that no container mounts a remote-storage credential file. The entrypoint's `mkdir` existed only for the in-container rclone binary; it is replaced by a half-configured-S3 warning.
