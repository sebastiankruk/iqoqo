# ai-cover-generation Specification

## Purpose

Define the LLM cover tiers: the consent and permission gates that must be satisfied before any model is called, the separation between local and cloud providers, the provenance recorded for each generated cover, and the requirement that a provider failure degrade rather than abort the pipeline.

## Requirements

### Requirement: LLM cover generation requires explicit consent

The cover pipeline MUST NOT call a language model to generate a cover unless the
instance has generation enabled AND the requesting user has granted the
`allow_generate_cover` permission. Absent either, the pipeline MUST fall through
to the deterministic Pillow fallback.

#### Scenario: The user has not consented

- **WHEN** a cover is missing and the requesting user has not granted
  `allow_generate_cover`
- **THEN** no LLM is called, cloud or local
- **AND** the deterministic Pillow fallback is used

#### Scenario: The instance has LLM generation disabled

- **WHEN** `ALLOW_LLM` is false
- **THEN** the LLM tier is skipped regardless of the user's permissions

### Requirement: Cloud providers require a separate permission

OpenAI and Gemini cover generation MUST require the `allow_cloud_llm` permission in
addition to `allow_generate_cover`, so a user who consents to generated covers can
still keep their images off third-party infrastructure.

#### Scenario: A user consents to generation but not to cloud providers

- **WHEN** a user grants `allow_generate_cover` but not `allow_cloud_llm`
- **THEN** no cloud provider is called
- **AND** generation falls back to a local provider, or to the Pillow fallback

#### Scenario: A user consents to cloud generation

- **WHEN** a user grants both permissions
- **THEN** a cloud provider MAY be used

### Requirement: Every generated cover records its provenance

A generated cover MUST record which provider produced it, so the UI can show
attribution and so a cached image is not regenerated.

#### Scenario: A cover is generated by a cloud provider

- **WHEN** OpenAI or Gemini produces an image
- **THEN** the stored cover records that provider as its source

#### Scenario: A cover is generated by a local provider

- **WHEN** a local Stable Diffusion instance produces an image
- **THEN** the stored cover records the local stable diffusion provider

#### Scenario: A previously generated cover is requested again

- **WHEN** a cover already generated and stored is requested again
- **THEN** it is served from the cache rather than regenerated
- **AND** the source is recorded as a cache hit

### Requirement: Generated images are watermarked and optimised before storage

A generated image MUST be watermarked and re-encoded to a bounded JPEG before it
is persisted, so a stored cover obeys the same size and format guarantees as a
downloaded one.

#### Scenario: An image is generated

- **WHEN** a provider returns raw image bytes
- **THEN** the image is watermarked
- **AND** it is re-encoded to a bounded JPEG before being written

### Requirement: A provider failure degrades to the next tier

A failure from any LLM provider MUST be confined to the LLM tier and MUST NOT
abort the cover pipeline.

#### Scenario: A provider errors or returns nothing usable

- **WHEN** an LLM cover provider raises, times out, or returns an unusable
  response
- **THEN** the failure is logged against the item identifier
- **AND** the pipeline continues to the deterministic Pillow fallback
- **AND** the item still receives a cover
