# Cover Provenance

## Purpose

Track and display the source of every cover image in the system, from API-sourced covers to AI-generated and PIL fallback covers, with accurate badge rendering and human-readable provenance labels in the UI.

## Requirements

### Requirement: Enhanced Fallback Cover Generation

The system SHALL generate visually polished fallback covers when all external API and LLM cover tiers fail. The fallback cover MUST include: a deterministic gradient background derived from the identifier, the title and author rendered with readable typography and drop shadows, and a prominent "powered by iqoqo" graphical footer centered at the bottom of the image. The footer MUST use a font size of at least 28px and be visually prominent. The cover SHALL NOT include a "Placeholder — contribute a cover" call-to-action text, as this adds visual noise without actionable value.

#### Scenario: Fallback cover generated for a new item with no external cover

- **WHEN** the cover pipeline exhausts all external API and LLM tiers for a manifestation
- **THEN** the system SHALL generate a fallback cover with a deterministic gradient, title, author, and a prominent "powered by iqoqo" footer, saving it to the covers directory with `cover_source` set to `"fallback_pil"`.

#### Scenario: Fallback cover footer is visually prominent

- **WHEN** a fallback cover is generated
- **THEN** the "powered by iqoqo" footer text SHALL be rendered at a minimum font size of 28px, centered horizontally, with a subtle horizontal rule or decorative element above it, and use a visible contrast color against the gradient background.

#### Scenario: Fallback cover does NOT include call-to-action text

- **WHEN** a fallback cover is generated
- **THEN** the cover SHALL NOT contain "Placeholder — contribute a cover" or any other call-to-action text.

#### Scenario: Deterministic gradient consistency

- **WHEN** the fallback cover is generated twice for the same identifier and title
- **THEN** the system SHALL produce the identical gradient color palette both times.

#### Scenario: Long title word wrapping

- **WHEN** a manifestation title exceeds the available width for single-line rendering
- **THEN** the system SHALL word-wrap the title across multiple lines within the image margins.

### Requirement: Cover Source Badge Accuracy

The system SHALL apply a source badge to every generated cover that accurately reflects its provenance tier. The badge mapping MUST include: `user_photo` → "U" (blue), `api_openlibrary` / `api_google_books` → "D" (gray), `api_allegro` → "A" (orange), `llm_gemini` → "G" (purple), `llm_openai` → "O" (green), `fallback_pil` → "S" (black), `api_igdb` → "I" (purple), `api_musicbrainz` → "M" (teal), `api_tmdb` → "T" (red).

#### Scenario: Badge applied to API-sourced cover

- **WHEN** a cover is downloaded from OpenLibrary
- **THEN** the system SHALL embed a gray "D" badge in the bottom-right corner of the saved cover image.

#### Scenario: Badge applied to fallback cover

- **WHEN** a PIL fallback cover is generated
- **THEN** the system SHALL embed a black "S" badge in the bottom-right corner.

### Requirement: Cover Provenance UI Display

The system SHALL display a human-readable provenance label near the cover image on item detail and manifestation detail pages. The label MUST translate the internal `cover_source` value into user-friendly text (e.g., `"api_openlibrary"` → "OpenLibrary", `"llm_gemini"` → "AI-generated", `"fallback_pil"` → "Placeholder", `"user_photo"` → "User photo").

#### Scenario: Item detail page shows cover provenance

- **WHEN** an authenticated user views an item detail page for a manifestation with `meta.cover_source` set to `"api_openlibrary"`
- **THEN** the system SHALL render a provenance indicator near the cover image displaying "Source: OpenLibrary".

#### Scenario: Fallback cover shows placeholder indicator

- **WHEN** a user views an item whose cover was generated by the PIL fallback
- **THEN** the system SHALL render a provenance indicator displaying "Source: Placeholder" and optionally a "Contribute a cover" link/trigger.

#### Scenario: No cover source metadata available

- **WHEN** a manifestation has a cover but no `cover_source` in its metadata (legacy data)
- **THEN** the system SHALL either display "Source: Unknown" or omit the provenance indicator entirely.
